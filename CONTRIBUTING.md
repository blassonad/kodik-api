# Contributing to `kodik-api-client`

Спасибо за интерес к проекту. `kodik-api-client` — типизированный асинхронный клиент публичного Kodik API. Мы приветствуем исправления, расширение покрытия API, документацию, тесты и предложения по улучшению эргономики.

> Не добавляйте в issue, pull request, commit, тесты или документацию токены Kodik, crates.io, GitHub и иные секреты. Для локальных примеров используйте `KODIK_API_TOKEN` из окружения.

## Начало работы

Используйте стабильный Rust не ниже версии, указанной в `Cargo.toml` в поле `rust-version`. Клонируйте fork, создайте тематическую ветку от основной ветки репозитория и выполняйте изменения в ней.

```bash
git clone https://github.com/<your-account>/kodik-api.git
cd kodik-api
cargo fmt --check
cargo test --all-targets
cargo clippy --all-targets -- -D warnings
cargo doc --no-deps
cargo package --allow-dirty
```

Перед отправкой pull request должны успешно выполняться все пять команд. `cargo package --allow-dirty` проверяет именно архив, который позднее будет отправлен в crates.io; его состав можно посмотреть через `cargo package --list`.[1]

## Принципы изменений

Публичные типы и методы являются контрактом библиотеки. Изменения, которые удаляют или меняют их смысл, считаются breaking changes и требуют соответствующего SemVer-релиза. Используйте типизированные enum для известных значений Kodik, но сохраняйте неизвестные серверные строковые поля в моделях там, где это повышает forward compatibility.

Все новые параметры API должны сопровождаться следующими изменениями:

| Область | Требование |
|---|---|
| `src/query.rs` | Тип поля, кодирование query/form parameter и локальная валидация, если параметр имеет инварианты. |
| `src/models.rs` | Serde-модель ответа, если API возвращает новые структурированные данные. |
| Тесты | Один или несколько тестов сериализации, валидации или десериализации без реального HTTP-запроса. |
| Документация | Rustdoc для публичного API и обновление `docs/API.md`/README, если пользовательский контракт меняется. |
| Changelog | Запись в разделе `Unreleased` файла `CHANGELOG.md`. |

Следуйте стандартному `rustfmt`. Сообщения коммитов должны быть ясными и в повелительном наклонении; рекомендуемый формат — Conventional Commits, например `feat: add release-year filter` или `fix: preserve episode screenshots`.

## Pull request

Один pull request должен решать одну логически связанную задачу. В описании объясните проблему, перечислите ключевые изменения, укажите выполненные проверки и отдельно отметьте любые изменения публичного API. Не смешивайте рефакторинг с изменением поведения, если это можно разнести на независимые PR.

Публикация на crates.io, создание GitHub release и изменения topics выполняются только maintainer’ом после проверки CI и `RELEASE.md`.

## Поведение в сообществе

Участники обязаны соблюдать [Code of Conduct](CODE_OF_CONDUCT.md). Уязвимости не следует обсуждать в публичном issue: используйте путь из [Security Policy](SECURITY.md).
